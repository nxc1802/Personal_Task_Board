## 1. Vulnerability Analysis & Implementation Details

### 1.1 Remediation of P1-2 (Tool Inventory & Mode Disconnect)
- **Problem:** Ambiguity between 10 read-only tools and 19 write tools, inconsistent defaults between CLI commands and server runners.
- **Remediation:**
  - `create_mcp_server(read_only: bool = True)` defaults to `True` (safe for any client).
  - When `read_only=True`, only tools 1–10 are registered on the FastMCP instance. Mutations are unregistered and return `ToolError: Unknown tool`.
  - When `read_only=False`, all 19 tools are registered.
  - Standard MCP Resources (`ptb://today-plan`, `ptb://tasks`, `ptb://system-health`) and Prompts (`morning_briefing`, `task_execution_context`) are registered across both modes as they are purely read-only inspection utilities.
  - `get_mcp_health` reports exact `tools_count` (10 or 19).

### 1.2 Remediation of P1-5 (Actor Impersonation via Parameter)
- **Problem:** MCP mutation tools accepted `actor: str = "CODING_AGENT"` without validating whether an agent was attempting to impersonate `ADMIN` or `SYSTEM`.
- **Remediation:**
  ```python
  RESERVED_PRIVILEGED_ACTORS = {"ADMIN", "SYSTEM", "ROOT", "SUPERUSER"}
  DEFAULT_MCP_ACTOR = "CODING_AGENT"

  def enforce_actor_policy(
      actor: Optional[str],
      admin_key: Optional[str] = None,
      default_actor: str = DEFAULT_MCP_ACTOR,
  ) -> str:
      if not actor or not str(actor).strip():
          return default_actor
      norm = str(actor).strip()
      if norm.upper() in RESERVED_PRIVILEGED_ACTORS:
          expected_admin = os.getenv("PTB_ADMIN_KEY")
          if expected_admin and admin_key and secrets.compare_digest(admin_key.strip(), expected_admin.strip()):
              return norm.upper()
          raise PermissionError(
              f"Impersonation forbidden: actor '{actor}' is reserved for administrative operations. "
              f"Coding agents must authenticate with valid admin credentials or use agent identity (e.g. '{default_actor}')."
          )
      return norm
  ```
  All mutation tools call `enforce_actor_policy` and return structured failure responses upon unauthorized impersonation.

### 1.3 Remediation of P1-8 (Leaked API Key Prefix)
- **Problem:** Line 297 of `server.py` contained hardcoded leaked key prefix `AQ.Ab8RN6J_9KlMg8fqmX0-veOqjJF9YtqgwO7Kk0vMreLgk-zgtg-mock`.
- **Remediation:** Replaced with safe generic test prefix checks (`not api_key.startswith("mock-") and not api_key.startswith("test-")`). Automated test `test_p1_8_no_leaked_credentials_in_server` asserts that the leaked string never returns.

### 1.4 Transport Security & No Unauthenticated Remote-Write (P0-2, W1-02)
- **Problem:** SSE transport at port 8001 had no authentication middleware, allowing unauthenticated network callers to execute mutations if write mode was enabled.
- **Remediation:**
  - Added `MCPSecurityMiddleware` to Starlette ASGI application returned by `server.sse_app()` and `server.streamable_http_app()`.
  - When `PTB_API_KEY` is set in the environment:
    - `/health` is exempt (HTTP 200 healthy / 503 not_ready).
    - `/sse` and `/messages` require valid key via `X-PTB-API-KEY`, `Authorization: Bearer <key>`, or `?api_key=<key>`.
    - Missing or invalid key yields `HTTP 401 Unauthorized` with `{"detail": "Missing API key..."}` or `{"detail": "Invalid API key."}`.
  - When `PTB_API_KEY` is unset: operates in development mode with warning log.

### 1.5 Destructive Action Safeguard
- **Problem:** `delete_task` could accidentally delete/dismiss tasks without confirmation.
- **Remediation:**
  - Added `confirm: bool = True` parameter to `delete_task`.
  - If `confirm=False`: returns `{"success": False, "task_id": clean_task_id, "error": "Destructive action aborted: confirmation required (set confirm=True to execute deletion)"}` without modifying task state.
  - Preserves backward compatibility when `confirm` is omitted.
