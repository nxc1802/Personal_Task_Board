## 2. Manifest Validation & Cryptographic Locking

### 2.1 Cross-Platform SHA-256 Calculation
Line-ending differences between Windows (`CRLF`) and Linux/macOS (`LF`) frequently cause checksum mismatch failures in cross-platform repositories. `benchmarks/manifest.py` solves this deterministically:

```python
def compute_file_sha256(file_path: Path) -> str:
    content = file_path.read_bytes()
    # Normalize CRLF -> LF for deterministic cross-platform hashing of text/JSON files
    normalized = content.replace(b"\r\n", b"\n")
    return hashlib.sha256(normalized).hexdigest()
```

### 2.2 Strict Rejection of `SKIP_VERIFY`
Unlike previous scripts that allowed bypassing verification:
- Any occurrence of `"SKIP_VERIFY"` or non-64-character hex strings immediately raises `ManifestValidationError`.
- Missing files listed in the manifest trigger immediate failure.
- Content modifications result in SHA-256 mismatch detection before any evaluation code executes.

### 2.3 Ground Truth Validation
Every sample in `samples.json` is validated upon loading against Pydantic models:
- Enforces valid `SourceType` (e.g. `MS_TEAMS`, `JIRA`, `CODING_AGENT`).
- Enforces valid `ClarityLabel` (`CLEAR`, `AMBIGUOUS`, `UNSPECIFIED`).
- Enforces valid `ControlType` (`TASK_SIGNAL`, `NOISE_CHITCHAT`, `STATUS_QUERY`, `NEGATION_REJECT`, `DUPLICATE_VARIANT`).
- Validates that persona fields follow canonical format `usr_<id>` and task IDs follow `tsk_<id>`.

## 3. Replay Runner & Anti-Inflation Design

### 3.1 Two-Pass Execution Cycle
To evaluate both initial extraction accuracy and idempotency durability, the `ReplayRunner` executes each sample through two consecutive passes:

1. **Clean Pass:**
   - Ingests raw event through `AcquisitionPipeline`.
   - Executes `ProcessingPipeline.process_raw_event()`.
   - Records elapsed execution time in `StepSnapshot.elapsed_ms`.
   - Captures created/updated tasks, raw event status, and checkpoint state.

2. **Replay Pass:**
   - Immediately re-ingests the identical raw event with identical payload.
   - Verifies whether a new task was created.
   - If `tasks_after_replay > tasks_after_clean`, records a duplicate idempotency violation:
     $$\text{duplicate\_tasks\_created} = N_{\text{replay}} - N_{\text{clean}}$$

### 3.2 Anti-Inflation and Honest Failure Handling
A critical requirement from W0-02 is preventing score inflation:
- **No Test Doubles in Production Runner:** The runner wires the real `AcquisitionPipeline` and `ProcessingPipeline` with production logic.
- **Graceful Infrastructure Handling:** When live LLM API keys (`GOOGLE_API_KEY`) or live Neo4j instances are unreachable, cases requiring live inference are categorized as `is_pending = True`.
- **Mathematical Anti-Inflation:**
  - `overall_verdict`: Set to `PENDING` if no hard failures occur, but never promoted to `PASS`.
  - Pass Rate formula:
    $$\text{Pass Rate} = \frac{\text{PASS Count}}{\text{Total Samples}} \times 100\%$$
    Because `PENDING` counts are in the denominator but not the numerator, unrunnable cases reduce the pass percentage honestly rather than inflating it.
  - Failure Precedence: If *any* case encounters an extraction mismatch, schema failure, or idempotency violation, the verdict is strictly `FAIL`, overriding any pending status.

## 4. 10-Dimension Scorecard & Statistical Rigor

The metric evaluator (`benchmarks/evaluator/scorecard.py`) synthesizes evaluation results across the 10 standardized dimensions:

| Dim # | Dimension Name | Primary Metric | Target Bar | Hard Gate | Mathematical Formulation |
|:---:|---|---|:---:|:---:|---|
| **1** | Task Extraction | Macro-F1 across 6 channels | $\ge 92.0\%$ | F1 $\ge 88.0\%$ | $\text{Macro-F1} = \frac{1}{\|S\|} \sum_{s \in S} F1_s$ |
| **2** | Noise & Negation Rejection | Noise Rejection Rate | $\ge 85.0\%$ | FPR $\le 10.0\%$ | $\text{NRR} = \frac{TN_{\text{noise}}}{TN_{\text{noise}} + FP_{\text{noise}}}$ |
| **3** | Attribution Accuracy | Exact Canonical ID Match | $\ge 90.0\%$ | Owner $\ge 85.0\%$ | $\text{Acc}_{\text{attr}} = \frac{N_{\text{owner\_match}}}{N_{\text{task\_expected}}}$ |
| **4** | Deadline Extraction | Exact UTC Match ($\pm$0s ISO) | $\ge 85.0\%$ | Exact ISO | $\text{Acc}_{\text{due}} = \frac{N_{\text{due\_match}}}{N_{\text{due\_expected}}}$ |
| **5** | Status Inference | State Machine Strict Enum | $\ge 90.0\%$ | No TODO=INPROG | $\text{Acc}_{\text{status}} = \frac{N_{\text{status\_match}}}{N_{\text{task\_expected}}}$ |
| **6** | Ranking & Prioritization | Kendall's $\tau$ correlation | $\ge 0.85$ | InProg #1 | $\tau = \frac{P - Q}{\sqrt{(P+Q+T) \cdot (P+Q+U)}}$ |
| **7** | Correlation Merging | False Merge Rate (FMR) | $0.0\%$ | FMR $== 0.0\%$ | $\text{FMR} = \frac{\text{False Merges}}{\text{Total Merge Ops}}$ |
| **8** | Lineage & Provenance | Orphan Task Count | $0$ | Lineage $100\%$ | $\text{Orphans} = N_{\text{tasks without evidence}}$ |
| **9** | Idempotency | Replay Duplicate Tasks | $0$ | Replay Dup $== 0$ | $\text{Duplicates} = N_{\text{replay}} - N_{\text{clean}}$ |
| **10**| System Reliability | $p95$ Ingestion Latency | $\le 1500\text{ms}$ | No crash | $p95 = \text{Percentile}_{95}(\{\text{latency}_i\})$ |

### 4.1 Wilson 95% Confidence Interval Formula
To ensure statistical validity on finite sample sizes, every rate and proportion $\hat{p} = \frac{k}{n}$ includes Wilson score 95% confidence intervals ($z = 1.96$):

$$w = \frac{1}{1 + \frac{z^2}{n}} \left( \hat{p} + \frac{z^2}{2n} \right) \pm \frac{z}{1 + \frac{z^2}{n}} \sqrt{\frac{\hat{p}(1 - \hat{p})}{n} + \frac{z^2}{4n^2}}$$

When $n = 0$, the interval defaults to $[0.0, 0.0]$.

### 4.2 Canonical Sort Contract
Kendall's $\tau$ assesses compliance with the canonical task ordering frozen by the orchestrator:
1. **Primary:** `status_rank ASC` (`IN_PROGRESS = 1`, `TODO = 2`, `BLOCKED = 3`, `DONE = 4`, `DISMISSED = 5`)
2. **Secondary:** `priority_score DESC`
3. **Tertiary:** `due_date ASC` (nulls sorted last)
4. **Quaternary:** `updated_at DESC`

## 7. Security and Compatibility Impact

1. **Integrity & Anti-Tampering:**
   - Datasets are bound to SHA-256 hashes in `manifest.json`. Any manual modification, accidental corruption, or silent edit immediately causes `ManifestValidationError`.
2. **Deterministic Deduplication & Idempotency Testing:**
   - The replay engine actively verifies that repeating acquisition raw events produces zero duplicate task entities in the repository, protecting graph databases from uncontrolled growth.
3. **No Secret / PII Leakage:**
   - Manifest loader and error reporters scrub sensitive authorization tokens and cookies before outputting diagnostic summaries.
4. **Clean Boundary Separation:**
   - Test doubles (`FakeDeterministicLLMExtractor`, `InMemoryTaskDomainRepository`) are strictly confined to `tests/support/`. The benchmark harness runtime relies solely on real production pipelines or its own dedicated repository implementations.
