## Executive Summary

Task **W3-02** implements the multi-source supervisor, configuration management, and end-to-end ingestion pipeline for Personal Task Board (PTB). It unifies all **9 source channels** under a single supervisor runtime:
1. `coding_agents` (Cursor, Claude Code, Antigravity logs)
2. `git` (Local Git repositories commits & branch logs)
3. `ms_teams` (Microsoft Teams Web network traffic interception via Playwright)
4. `ms_outlook` (Microsoft Outlook Web and Graph REST mail)
5. `jira` (Atlassian Jira Cloud/Server issues)
6. `shortcut` (Shortcut.com stories & epics)
7. `confluence` (Atlassian Confluence spaces & pages)
8. `github` (GitHub REST / GraphQL issues, PRs, and review comments)
9. `slack` (Slack Bot / Web API conversations and threads)

All 9 sources are declared with strict typing and schema contracts in `config/sources.yaml`. Remote enterprise/cloud sources lacking local credentials default safely to `enabled: false`.

The orchestration layer in `services/acquisition/src/ptb_acquisition/pipeline.py` and `scripts/ptb_cli.py` has been hardened to provide:
- **Partial Failure Tolerance**: Failures in one source (e.g., HTTP 429 rate limit backoff, HTTP 401/403 authorization expiry, or network socket drop) are completely isolated and never crash the supervisor loop or prevent healthy adapters from syncing.
- **Dynamic Rate-Limit Backoff**: `AdapterPollingRunner` dynamically respects `retry_after_seconds` received from `AdapterRateLimitError` or applies exponential backoff with jitter.
- **Replay Safety**: Repeated ingestion of existing events produces **zero duplicate raw events or unified tasks**.
- **Checkpoint Persistence**: Checkpoints are persistently keyed by composite identity `(tenant_id, source_type, stream_id)` and survive process restarts, automatically resuming via `poll_incremental` instead of full backfill.
- **Truthful Doctor Auditing**: `ptb doctor` inspects all 9 sources and reports truthful states (`READY`, `NOT_CONFIGURED`, `AUTH_REQUIRED`, `DEGRADED`) while preserving exit code 0 when core system infrastructure is healthy.
- **On-Demand Synchronization**: `ptb ingest --source <all|name>` allows selective or full-batch synchronization with detailed metrics.

## Technical Implementations

### 1. `config/sources.yaml`
- Redefined all 9 sources with uniform schema:
  - `enabled`: boolean flag (true only for `coding_agents` and `git`).
  - `tenant_id`: multi-tenant identifier scoping.
  - `rate_limit`: `max_requests_per_minute`, `burst_limit`, `retry_after_default_seconds`.
  - `checkpoint`: `cursor_strategy`, `auto_resume`.
- Remote sources include environment variable fallbacks (e.g. `api_token_env: JIRA_API_TOKEN`).

### 2. `services/acquisition/src/ptb_acquisition/pipeline.py`
- **Adapter Registry & Lookup**: Added `register_adapter(name_or_adapter, adapter=None, name=None)`, `get_adapter(name_or_source_type)` with enum/alias normalization (`coding_agent` vs `coding_agents`, `ms_outlook` vs `outlook`), and `list_registered_adapters()`.
- **Durable Replay Deduplication**: Enhanced `ingest_event(record)` to check `raw_event_repo` idempotency before persisting, ensuring deduplication succeeds even when pipeline instances are re-created across process restarts.
- **Partial Failure Isolation**: Enhanced `sync_adapter(raise_on_error=False)` to catch adapter exceptions, increment `_stats["errors"]`, and log telemetry without failing.
- **Multi-Source Synchronization**: Implemented `sync_source(name_or_source_type)` for on-demand single-source execution, and `sync_all_registered()` returning structured per-adapter reports (`status`, `count`, `streams`, `error`).
- **Composite Identity Checkpoints**: Checkpoints are stored and retrieved per `(tenant_id, source_type, stream_id)`.

### 3. `scripts/ptb_cli.py`
- **`AdapterPollingRunner`**:
  - Refactored `poll_once() -> float` to execute single cycles and compute backoff intervals.
  - Dynamically extracts `retry_after_seconds` from `AdapterRateLimitError` (HTTP 429) or applies exponential backoff (`min_backoff * (multiplier ** failures)`).
  - Emits telemetry bug log `BugCode.PTB_L1_002` when adapters experience synchronization errors.
- **`PTBProcessSupervisor`**:
  - Accepts `sources_config` and `sources_config_path` in `__init__`, eagerly parsing configuration.
  - Wires up all 9 adapters (`coding_agents`, `git`, `jira`, `shortcut`, `confluence`, `github`, `slack`, `outlook`, `teams`).
  - Dynamically respects configured poll intervals from `sources.yaml`.
  - Accepted `port` keyword argument as an alias to `app_port`.
- **`cmd_doctor`**:
  - Truthfully audits all 9 sources against live configuration and credentials.
  - Assigns `READY`, `NOT_CONFIGURED`, `AUTH_REQUIRED`, or `DEGRADED`.
  - Classifies unconfigured enterprise sources as warnings (`is_warn = True`), allowing exit code 0 when core infrastructure (Python >= 3.11, Docker, Neo4j) is healthy.
- **`cmd_ingest`**:
  - Supports `--source` choices: `all`, `coding_agents`, `git`, `jira`, `shortcut`, `outlook`, `confluence`, `github`, `slack`, `teams`.
  - Runs on-demand sweeps with full error isolation and returns formatted stats.

## Security & Compatibility Impact

1. **Multi-Tenant Scoping (P1-4 Protection)**:
   - Checkpoints are strictly partitioned by `(tenant_id, source_type, stream_id)`. Tenant A cannot access, overwrite, or advance the cursor of Tenant B.
2. **Safe Defaults for Cloud Sources**:
   - Remote sources (`jira`, `shortcut`, `confluence`, `github`, `slack`) remain `enabled: false` by default, eliminating accidental unauthenticated network requests or credential exposure during setup.
3. **No Fake Verifications (P0-7 / Anti-Mock Guard)**:
   - Live external integrations without credentials explicitly emit `pytest.skip` marked `PENDING` rather than simulating successful network calls with fake doubles.
4. **Resilience & Stability**:
   - Unhandled 429/401/socket errors in one source cannot crash the supervisor loop, guaranteeing high availability for remaining sources.
