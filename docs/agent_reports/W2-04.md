## 2. Technical Architecture & Design

### 2.1 Jira Adapter (`jira_adapter.py`)

#### Cloud vs Server API Compatibility
Jira Cloud natively supports REST API v3 and Atlassian Document Format (ADF), whereas Jira Server / Data Center supports REST API v2 with wiki markup and Personal Access Tokens (PAT).
```
                      +-----------------------------+
                      |      JiraAdapter            |
                      +--------------+--------------+
                                     |
                     API Version Detection / Fallback
                                     |
              +----------------------+----------------------+
              |                                             |
     [Jira Cloud (v3)]                            [Jira Server (v2)]
- Auth: Basic (email:api_token)              - Auth: Bearer (PAT) or Basic
- ADF json payload parsing                   - Plain text / wiki markup
- Endpoint: /rest/api/3/search               - Endpoint: /rest/api/2/search
- Endpoint: /rest/api/3/myself               - Endpoint: /rest/api/2/myself
```
If an adapter configured with `api_version="3"` receives an HTTP 404 on an API endpoint, it catches `AdapterStreamNotFoundError`, automatically resets `self.api_version = "2"`, and re-routes the request to `/rest/api/2/...`.

#### Rich ADF Parser
ADF is represented as a JSON AST node tree. `_extract_jira_text` recursively renders AST nodes into clean Markdown-compatible text:
- `heading`: Prefixes with `#` according to level attribute (`#`, `##`, `###`).
- `paragraph`: Renders text children and appends double newlines.
- `bulletList` & `orderedList`: Renders list items with `- ` or `1. `, `2. `.
- `codeBlock`: Renders ````lang ... ```` syntax.
- `blockquote`: Prefixes lines with `> `.
- `table`, `tableRow`, `tableCell`: Renders markdown table format (`| col1 | col2 |`).
- `mention`: Formats as `@user`.
- `emoji`: Extracts short name (e.g. `:rocket:`).
- `marks`: Preserves inline formatting (e.g., strong, code `` `text` ``, link `[text](url)`).

#### Status Transitions & Metadata Tracking
The search API payload expands `changelog`. Historical transitions are parsed:
```python
transitions.append(f"[{h_created}] {from_str} -> {to_str} by {h_author}")
```
The issue's normalized text embeds:
```
[DEV-201] Implement durable ingestion pipeline
Status: In Development | Category: In Progress | Priority: High | Type: Task | Assignee: Tech Lead | Labels: backend, acquisition

Recent Transitions:
[2026-10-01T08:30:00.000+0000] To Do -> In Development by Product Manager
```

#### Comments Ingestion
When `include_comments=True`, `fields.comment.comments` is inspected. Each active comment yields a child `RawEventRecord`:
- `external_id`: `{issue_key}-comment-{comment_id}`
- `parent_external_id`: `{issue_key}`
- `conversation_or_project_id`: Project key
- `author_external_id`: Comment author's `accountId` or username
- `deep_link`: `{base_url}/browse/{issue_key}?focusedCommentId={comment_id}`
- `normalized_text`: `[{issue_key} Comment by {author}]\n\n{comment_body}`

### 2.2 Shortcut Adapter (`shortcut_adapter.py`)

#### Stories & Workflow States
Shortcut stories are fetched via `/stories/search` (POST with query and cursor). Workflow states are resolved into names using `self._workflow_states`:
```
[9901] (feature) Design & Implement Distributed Checkpoint Journal
State: In Development | Owners: uuid-owner-1, uuid-owner-2

Ensure zero data loss during node failover with SQLite and Neo4j MERGE.
```

#### Archived Stories
When `story.get("archived")` is true:
- Appends `[ARCHIVED]` tag to normalized text header.
- Sets `raw_payload["archived"] = True`.
- In `_build_search_query`: if `include_archived` is false (default), appends `!is:archived` to the query. If `include_archived` is true, allows archived stories through.

#### Comments Ingestion
Stories have nested `comments` arrays. Each non-deleted comment yields a child `RawEventRecord`:
- `external_id`: `{story_id}-comment-{comment_id}`
- `parent_external_id`: `{story_id}`
- `deep_link`: `{app_url}#comment-{comment_id}`
- `event_timestamp`: Timestamp of comment update or creation

#### Cursor-Based Pagination
Shortcut returns cursor tokens in the `"next"` field of search responses. The adapter supports:
1. Direct cursor tokens (e.g., `"token_123"`).
2. Full URL next pointers (e.g., `"https://api.app.shortcut.com/api/v3/stories/search?next=token_123"`), parsing query strings via `urllib.parse`.
3. Cycle guard: tracks `seen_cursors` set to break immediately if the remote API emits repeated cursors.

---

### 2.3 Shared Resilience & Rate Limiting Contract

Both adapters route HTTP requests through `execute_with_retry` and classify HTTP response codes:
- **HTTP 401, 403:** Raises `AdapterAuthenticationError`. Does NOT retry, failing fast to prevent account lockouts.
- **HTTP 429:** Parses `Retry-After` header (in seconds, defaulting to 5.0s), calls `await self.handle_rate_limit(retry_after)` to pause execution, and retries with backoff.
- **HTTP 404:** Raises `AdapterStreamNotFoundError`.
- **HTTP 500, 502, 503, 504 & Network Timeouts:** Raises `AdapterTransientError`, retried via `execute_with_retry` with exponential backoff and jitter.

### 2.4 Health Inspection States
Both adapters implement `health() -> Dict[str, Any]` adhering to `AdapterHealthStatus`:
- Missing credentials or base URL: `configured: False`, `status: "not_configured"`.
- Authentication error (401/403) on validation ping: `configured: True`, `status: "auth_required"`.
- Transient error (5xx / timeout) on validation ping: `configured: True`, `status: "degraded"`.
- Successful ping: `configured: True`, `status: "healthy"`.

## 4. Security & Multi-Tenant Compatibility Impact

1. **Authentication Token Safety:**
   - Both adapters accept credentials via environment variables (`JIRA_API_TOKEN`, `JIRA_PAT`, `SHORTCUT_API_TOKEN`) or constructor arguments.
   - Credentials are never exposed in log statements, event payloads, or normalized text.
   - Missing tokens cleanly yield `configured: False` and `status: "not_configured"` without throwing unhandled exceptions.

2. **Cross-Tenant Isolation:**
   - Every `RawEventRecord` emitted has `tenant_id` set from `self.tenant_id`.
   - `idempotency_key` and `checkpoint_id` explicitly hash `tenant_id`, guaranteeing cryptographic namespace isolation across tenants.
   - Tests confirm tenant A cannot observe or mutate tenant B checkpoints or events.

3. **External System Protection:**
   - Rate limit responses (HTTP 429) enforce pauses using the remote provider's `Retry-After` header, preventing external API bans or quota depletion.
   - Authentication errors (401/403) fail fast without retrying.
