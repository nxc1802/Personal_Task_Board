# W4-02 — Identity Resolution, Persona Invariant Enforcement & Attribution Calibration

**Wave:** 4 | **Role:** Implementation | **Dependencies:** W3-04 | **Status:** PASS

## 1. Executive Summary & Root-Cause Analysis
From the Wave 3 Failure Ledger, 67 cases failed with `attribution_requester` and 62 cases with `attribution_owner`.

### Root Causes Identified & Addressed:
1. **Requester Attribution Fallback (67 cases):**
   - *Cause:* In direct tasks and quote/replies (Slack, Teams, Email), the message author or quoted parent author is the requester. However, LLM extractions occasionally omitted `requester_name`, or the pipeline required `validated_candidate.requester_name` to be pre-populated before executing `_resolve_identity`.
   - *Fix:* In `services/processing/src/ptb_processing/pipeline.py` step 5b, implemented an authoritative fallback cascade:
     `req_name = validated_candidate.requester_name or parsed.quoted_author_raw or parsed.actual_author_raw or raw_event.author_display_name`.
     Extracted `req_ext_id` from `raw_event.author_external_id` or structured payload reporter account ID. If exact match is found, canonical ID is attached and `requester_name` is populated.
2. **Owner Attribution & Account Mapping (62 cases):**
   - *Cause:* In Jira tickets, the assignee was stored in `raw_payload.fields.assignee.accountId` (`cuong.dam_jira`). In Slack messages, mentions were formatted as `<@cuong.dam>`. The resolver did not map canonical person IDs or email username prefixes directly, causing `owner_canonical_id` to remain `None`.
   - *Fix:* Enhanced `IdentityResolver` in `services/processing/src/ptb_processing/identity/resolver.py`:
     - Added exact `person_id` matching.
     - Added email prefix extraction matching (e.g. `cuong.dam@company.com` matches `cuong.dam`).
     - Maintained strict invariant: if an email is provided and differs from the registered primary email, exact match is strictly prohibited (disallowing false merges across different users with similar names).
     - Enhanced `pipeline.py` step 5a to extract assignee info from `raw_payload["fields"]["assignee"]`.
