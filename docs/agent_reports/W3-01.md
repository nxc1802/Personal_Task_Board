### 3.3 Live CRUD Lifecycle & Neo4j State Persistence
A dedicated task was exercised through the entire production lifecycle:
1. **CREATE**:
   - UI: Triggered `openCreateTaskModal()`, filled `#createTaskTitle`, `#createTaskProject`, `#createTaskPriority` (78.0), `#createTaskDueDate`, and submitted via `#btnSubmitCreateTask`.
   - Neo4j: Polled `GET /api/tasks?project=...`, confirming node creation with status `TODO`, `priority_score=78.0`, and authoritative status timestamp.
2. **READ / VERIFY**:
   - UI: Task card rendered in `#tasksComponentsContainer` with priority badge, project pill, and status badge.
   - API: `GET /api/tasks/{task_id}` confirmed complete attributes in Neo4j.
3. **EDIT (PATCH)**:
   - UI: Invoked `openEditTaskModal('{task_id}')`, updated title with `[UPDATED]` suffix, priority to `92.0`, and submitted `#btnSaveEditTask`.
   - Neo4j: `GET /api/tasks/{task_id}` confirmed immediate PATCH update of `title`, `priority_score`, and description in the database.
4. **STATUS TRANSITION**:
   - UI: Invoked `updateTaskStatus('{task_id}', 'IN_PROGRESS')` -> card updated to `IN_PROGRESS`.
   - Neo4j: `GET /api/tasks/{task_id}` verified status `IN_PROGRESS` and status transition audit entry created.
   - UI: Invoked `updateTaskStatus('{task_id}', 'DONE')` -> card marked `DONE`.
   - Neo4j: verified status `DONE`.
5. **PERSISTENCE ACROSS FULL RELOAD**:
   - Triggered browser `page.reload(wait_until="networkidle")`.
   - Re-queried DOM and backend API: Task state remained strictly `DONE` with priority `92.0`. Proven that UI state is Neo4j-backed and not transient memory.
6. **DELETE (SOFT DELETE / DISMISSED)**:
   - Triggered `deleteTask('{task_id}')` with browser confirmation dialog accepted (`dialog.accept()`).
   - UI: Task card optimistically removed from the view.
   - Neo4j: Backend updated task status to `DISMISSED` with actor audit trail (`USER`).

### 3.4 Review Queue Approve & Dismiss Workflow
- Candidate tasks in the Review Queue (`/api/review`) were evaluated live:
  - **Approve**: Invoking `approveReviewItem('{cand_a_id}')` transitions review item from `pending` to `auto_approved` with status `TODO` in Neo4j.
  - **Dismiss**: Invoking `dismissReviewItem('{cand_b_id}')` transitions item to `DISMISSED` in Neo4j and removes it from the review queue.

### 3.5 Error & Outage Handling
- **Optimistic UI Rollback**:
  - Simulated backend HTTP 500 error on `/api/tasks/{id}/status` via Playwright route interception.
  - UI immediately showed optimistic update to `IN_PROGRESS`.
  - Upon receiving HTTP 500, UI displayed error toast (`"Lỗi đồng bộ trạng thái: Simulated Database Connection Failure"`) and automatically rolled back in-memory cached status and DOM representation to `TODO`.
  - Simulated backend HTTP 500 on `/api/tasks/{id}/delete`: Task card was automatically restored to the list.
- **Double-Click & Parallel Submission Prevention**:
  - `isSubmittingTask` lock verified: Clicking `#btnSubmitCreateTask` sets flag, disables button (`btn.disabled = true`), and changes label to `"Đang tạo... ⏳"`.
  - Rapid parallel calls to `submitCreateTask()` proved that only 1 task is created in Neo4j, preventing duplicate records.
  - `pendingStatusUpdates` Set verified preventing concurrent race conditions on rapid status clicks.
- **Authentication Failure Banners**:
  - Intercepted API calls with 401 Unauthorized (`Missing X-PTB-API-KEY`).
  - Verified `#globalSystemBanner` displays `"API AUTH REQUIRED: Missing or invalid X-PTB-API-KEY"`.
  - Verified `#statusText` updates to `"API Auth Required"`.
- **Backend Outage Banners**:
  - Intercepted connection with network abort (`connectionrefused`).
  - Verified `#globalSystemBanner` displays `"[PTB-OWUI-001] APPLICATION SERVICE OFFLINE"`.
  - Verified `#statusText` updates to `"Application Offline"`.

### 3.6 Cross-Tenant Isolation
- Inquiries with distinct tenant user identities (`user_id="tenant_alpha"` vs `user_id="tenant_beta"`) verified through `/api/today`, `/api/waiting`, and `/api/forgotten`.
- Neo4j queries enforce user context separation; Tenant A commitments and blocked items are not exposed to Tenant B.

### 3.7 Zero Secret & Token Leakage Audit
- Verified that `_sanitize_for_logging()` masks sensitive substrings matching:
  - `Bearer <token>` -> `Bearer ***REDACTED***`
  - `X-PTB-API-KEY: <key>` -> `X-PTB-API-KEY: ***REDACTED***`
  - Dict keys containing `key`, `token`, `password`, `auth`, `secret`
- Verified during live browser execution with configured API keys that raw secrets are never exposed in DOM inner text or console output.
