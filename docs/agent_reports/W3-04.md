### Root Cause Cluster 1: Requester Attribution Loss
- **Cases Affected:** 67 samples (e.g. `ptb500-001-teams-direct_task`, `ptb500-002-teams-direct_task`, `ptb500-003-teams-direct_task`, `ptb500-004-teams-direct_task`, `ptb500-086-outlook-direct_task`, `ptb500-087-outlook-direct_task`)
- **Symptoms:** `requester_canonical_id` is set to `None` while expected persona ID is valid (e.g., `expected='lead.tran', actual=None`).
- **Root Cause Component:** `ProcessingPipeline._resolve_identity` and `LLMStructuredExtractor.extract_from_parsed`.
- **Suspected Code:**
  - `services/processing/src/ptb_processing/pipeline.py:248-275`
  - When a message is a direct command or request without quote blocks, the LLM sets `requester_name = None`. `pipeline.py` checks `if validated_candidate.requester_name:`, skipping requester resolution entirely rather than falling back to `raw_event.author_external_id` / `raw_event.author_display_name`.
- **Severity:** **HIGH**
- **Reproducible Command:**
  ```bash
  python -m benchmarks.cli run --dataset-dir benchmarks/dataset/ptb_500 --case-id ptb500-001-teams-direct_task
  ```
- **Target Wave 4 Task:** **W4-02 (Attribution & Identity Resolution)**: Implement author-as-requester fallback when explicit requester name is absent in direct action requests.
