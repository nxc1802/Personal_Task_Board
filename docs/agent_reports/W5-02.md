## 2. Documentation Audit & Truth-in-Advertising Reconciliation

### 2.1 FastMCP Tool Count Reconciliation (10 vs 19 Tools)
- **Code Reality**: `services/mcp/src/ptb_mcp/server.py` implements two distinct operational profiles:
  - **Read-Only Profile (`read_only=True`, Default)**: Registers exactly **10 query tools** (`get_today_tasks`, `get_tasks`, `get_task_context`, `get_waiting_items`, `get_forgotten_commitments`, `get_review_queue`, `search_decisions`, `search_lessons_learned`, `search_context`, `get_source_health`). This default mode ensures that external Coding Agents cannot perform unauthorized mutations, deletions, or task status updates without explicit developer consent.
  - **Full Lifecycle Profile (`read_only=False`)**: Registers **19 tools** (the 10 read-only query tools plus 9 mutation/admin tools: `approve_task`, `ask_ptb_agent`, `create_task`, `delete_task`, `dismiss_task`, `record_decision`, `record_lesson_learned`, `update_task`, `update_task_status`).
- **Documentation Alignment**: `README.md`, `Task/README.md`, and `DEPLOYMENT.md` now clearly distinguish the default 10 read-only query tools from the 19 full lifecycle tools, eliminating ambiguity.

### 2.2 Benchmark Score Truthfulness (PTB-Bench-500)
- **Code Reality**: The locked PTB-Bench-500 dataset (`benchmarks/dataset/ptb_500/`) was empirically evaluated during Wave 3, establishing a baseline overall accuracy of 48.2% (`reports/benchmarks/benchmark_500.md`). Root causes across multi-channel parsing, temporal date extraction, candidate correlation, identity resolution, and Neo4j single-store persistence were systematically remediated during Wave 4.
- **Documentation Alignment**: Replaced outdated spec claims of hypothetical 100% benchmark passes in `Task/README.md` with transparent disclosure of the 48.2% baseline and Wave 4 targeted architectural remediations.

### 2.3 Single UI Tab Architecture & OpenWebUI Version
- **Code Reality**: OpenWebUI v0.5.10 runs on port `3000` with container-to-host network routing (`http://host.docker.internal:8000`), while browser clients interact with backend REST APIs via `http://127.0.0.1:8000`. The interactive board operates through a self-contained Kanban component (`integrations/openwebui/board/ptb_board.html`) without monorepo package coupling (`import ptb_contracts`).
- **Documentation Alignment**: Verified and documented across `RUN_GUIDE.md` and `SETUP.md`.

### 2.4 Status & Conditional Readiness
- **Code Reality**: Local, offline, git, agent watchers, and fixture-based pipelines are fully operational and pass all automated tests. External integrations requiring third-party credentials (Jira API tokens, Shortcut API tokens, Microsoft Graph OAuth secrets) are legitimately marked `PENDING` until configured by the deploying organization.
- **Documentation Alignment**: Declared status as `CONDITIONALLY_READY` rather than premature unconditional readiness.
