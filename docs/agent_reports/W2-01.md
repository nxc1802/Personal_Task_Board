## 2. OpenWebUI Tool & Function Registration Mechanism (v0.5.10 Pinned)

OpenWebUI v0.5.10 discovers and registers tools and functions through two distinct pathways:

```
+-------------------------------------------------------------------------------+
|                      OpenWebUI v0.5.10 Registration Architecture              |
+-------------------------------------------------------------------------------+
                                      |
         +----------------------------+----------------------------+
         |                                                         |
         v                                                         v
 [Path A: Direct DB Registration]                     [Path B: REST API Registration]
   File: webui.db (SQLite/Peewee)                       Endpoints:
   - Table: tool                                          - POST /api/v1/tools/create
     Columns: id, user_id, name, content,                  - POST /api/v1/tools/id/{id}/update
              specs, meta, valves, access_control,        - POST /api/v1/functions/create
              created_at, updated_at                      - POST /api/v1/functions/id/{id}/update
   - Table: function                                    Headers:
     Columns: id, user_id, name, type, content,           - Authorization: Bearer <OPENWEBUI_API_KEY>
              meta, valves, is_active, is_global,       Payload:
              created_at, updated_at                      - {id, name, content, meta: {manifest}}
                                      |
                                      v
                       [Runtime Execution by OpenWebUI]
         - Tool Call: Model invokes tool function -> OpenWebUI dynamically invokes
           method on Tools instance with parameter mapping (ignoring __user__).
         - Filter Function: Intercepts conversation in inlet() (pre-prompt) and
           outlet() (post-generation).
         - Action Function: Intercepts /board prompt shortcuts in inlet() and renders
           interactive HTML board artifacts when clicked via action().
```

### Key Registration Invariants
1. **Tool Specs Generation**: OpenWebUI expects an OpenAI-compatible JSON schema for tools (`specs` column). At startup or installation, inspects class `Tools` methods, extracting parameter types, default values, and docstrings (`:param <name>: ...`). Parameters named `self`, `extra_params`, and `__user__` are automatically omitted from function schemas, allowing runtime user injection.
2. **Function Types**: OpenWebUI supports three function types: `"action"` (`Action` class), `"filter"` (`Filter` class), and `"pipe"` (`Pipe` class).
3. **Valves Configuration**: Both `Tools` and `Function` define an inner Pydantic `Valves(BaseModel)` class. OpenWebUI surfaces these fields in the web admin UI for users to configure endpoints, API keys, and timeouts.
4. **Access Control & Permissions**: The `access_control` and `valves` columns preserve access definitions across restarts.

## 3. Implementation Details

### 3.1 `integrations/openwebui/tools/ptb_tools.py`
Enhanced the `Tools` class to provide complete coverage of the PTB REST API:
- **Authentication**: `Valves.api_key` (defaulting to `PTB_API_KEY` env var) is injected into every HTTP request via `X-PTB-API-KEY` and `Authorization: Bearer <key>`.
- **Bounded Timeout**: `timeout` is bounded between `1.0s` and `30.0s`.
- **Transient Retries**: Retries up to `max_retries` (default 2) with backoff on transient network errors or HTTP 5xx responses. Does NOT retry on 4xx client errors.
- **Error Normalization**:
  - `401 Unauthorized` -> `❌ [PTB-OWUI-401] XÁC THỰC THẤT BẠI: ...` (no longer falsely claims application service is offline).
  - `403 Forbidden` -> `❌ [PTB-OWUI-403] TỪ CHỐI TRUY CẬP: ...`
  - `404 Not Found` -> `❌ [PTB-OWUI-404] KHÔNG TÌM THẤY: ...`
  - `400 Bad Request` -> `❌ [PTB-OWUI-400] DỮ LIỆU KHÔNG HỢP LỆ: ...`
  - `5xx / Offline` -> `❌ [PTB-OWUI-001] APPLICATION SERVICE OFFLINE ...`
- **Token Redaction (`_sanitize_for_logging`)**: Masks API keys and bearer tokens from stderr structured logging.
- **Mutation Authorization Check (`_check_mutation_permission`)**:
  - Checks `valves.allow_mutations`. If False, blocks mutations immediately.
  - Checks `__user__["role"]`. If `"read_only"` or `"pending"`, rejects mutations.
  - Dynamically sets `actor` to `OPENWEBUI:<user_name>` to eliminate impersonal spoofing.
- **No Optimistic Success**: All mutations (`create_task`, `edit_task`, `update_task_status`, `delete_task`, `approve_task`, `dismiss_task`) verify backend response confirmation (presence of ID, `success: True`, or confirmed status) before reporting success.
- **Comprehensive API Call Paths**:
  1. `get_today_tasks(limit=5, __user__=None)`: Morning briefing with priorities, risk warnings, and canonical sort.
  2. `get_tasks(status=None, project_key=None, source=None, limit=10, __user__=None)`: Multi-criteria filtering.
  3. `get_task_detail(task_id, __user__=None)`: Complete task context with blockers, dependents, evidences, and Graphiti decisions/lessons.
  4. `get_review_queue(__user__=None)`: Candidate review inbox.
  5. `approve_task(review_id, __user__=None)`: Approves candidate to active TODO task.
  6. `dismiss_task(review_id, __user__=None)`: Dismisses candidate.
  7. `update_task_status(task_id, new_status, __user__=None)`: Validates canonical statuses (`TODO`, `IN_PROGRESS`, `BLOCKED`, `DONE`, `DISMISSED`) and updates status.
  8. `edit_task(task_id, title=None, description=None, project_key=None, due_date=None, priority_score=None, __user__=None)`: Issues `PATCH /api/tasks/{task_id}`.
  9. `create_task(title, description="", project_key="GLOBAL", due_date="", priority_score=50.0, __user__=None)`: Creates new UnifiedTask.
  10. `delete_task(task_id, __user__=None)`: Dismisses/deletes task via `POST /api/tasks/{task_id}/delete`.
  11. `get_waiting_items(__user__=None)`: Retrieves blocked items waiting on others.
  12. `get_forgotten_commitments(__user__=None)`: Retrieves stale chat promises.
  13. `search_knowledge(query, knowledge_type="all", project_key=None, limit=5, __user__=None)`: ADR & lessons search.
  14. `get_source_health(__user__=None)`: Adapter connectivity report.
  15. `render_board_artifact()`: Renders interactive HTML artifact.

### 3.2 `integrations/openwebui/functions/ptb_board_action.py`
- Upgraded `Action` class with `Valves.api_key`, `Valves.request_timeout`, and `Valves.allow_mutations`.
- Propagates `X-PTB-API-KEY` and Bearer auth headers.
- Enhanced `inlet` commands:
  - `/board view` or `/board`: Displays interactive board artifact.
  - `/board today`: Morning briefing summary with top tasks.
  - `/board tasks`: Displays recent tasks.
  - `/board review`: Displays candidates in review queue.
  - `/board approve <id>`: Checks mutation permissions and verifies BE confirmation before acknowledging.
  - `/board dismiss <id>`: Checks mutation permissions and verifies BE confirmation before acknowledging.
- Token redaction and HTTP error normalization.

### 3.3 `integrations/openwebui/functions/ptb_filter.py`
Implemented the previously empty `ptb_filter.py` as an OpenWebUI context grounding filter:
- Class `Filter` with `Valves`:
  - `app_service_url`, `api_key`, `inject_task_context` (default True), `request_timeout` (3.5s), `max_retries` (1).
- **`inlet(body, __user__)`**:
  - Detects task-related queries in the user prompt (e.g. `today`, `kế hoạch`, `công việc`, `tasks`, `deadline`, `review queue`, `/today`, `/tasks`).
  - Calls `GET /api/today` via authenticated HTTP request with timeout.
  - Injects authoritative `[Personal Task Board Grounding Context (Source of Truth)]` block into the system message.
  - Gracefully degrades: if the backend is offline or returns an error, passes the message through cleanly without crashing the conversation.
- **`outlet(body, __user__)`**: Pass-through for clean post-processing.
- **Strict Compliance**: Zero internal PTB dependencies (standard library + Pydantic only), no forbidden mock tokens.

## 5. Security & Compatibility Assessment
1. **API Key Security (P0-2, P1-8)**:
   - All outgoing requests from OpenWebUI plugins include `X-PTB-API-KEY` and `Authorization: Bearer <key>`.
   - Secret tokens are automatically scrubbed via `_sanitize_for_logging` prior to writing to stderr.
   - HTTP 401 and 403 errors are accurately reported without dumping tokens into chat outputs.
2. **Actor & Tenant Provenance (P1-5, P1-4)**:
   - When OpenWebUI passes `__user__`, the user identity is used to construct `actor = "OPENWEBUI:<user_name>"` and `user_id = "<id>"`, preventing impersonation.
   - Read-only users are forbidden from executing mutations.
3. **No Secondary Database**: OpenWebUI tools and functions store zero task state; the authoritative source of truth is the PTB Application Service backed by Neo4j.
4. **Backward Compatibility**: All existing signatures and expected methods from Phase R11/R12 remain intact. Fallback parameter handling ensures backward compatibility with earlier OpenWebUI versions.
