# W5-01 — Hardening Release Pipeline, Container Security & CI Gates Report

## 1. Executive Summary

W5-01 completes the release engineering hardening, container security isolation, and CI gate infrastructure for the Personal Task Board (PTB) system. All production deployment specifications have been audited and verified against strict zero-trust standards, ensuring that no unauthenticated administrative operations or unencrypted public endpoints can be exposed in production environments.

The automated release readiness gate test suite (`tests/test_release_readiness.py`) passed 14/14 tests cleanly, confirming zero runtime mocks, zero in-memory fallback stores, truthful health reporting, and complete tenant isolation across all acquisition and persistence layers.

---

## 2. Hardening & Security Audit

### 2.1 Container & Network Isolation (`docker-compose.prod.yml`)
- **Port Bindings**: All service ports are strictly bound to localhost (`127.0.0.1`):
  - Neo4j HTTP Browser: `127.0.0.1:7474:7474`
  - Neo4j Bolt Protocol: `127.0.0.1:7687:7687`
  - PTB REST API: `127.0.0.1:8000:8000`
  - PTB FastMCP SSE: `127.0.0.1:8001:8001`
  - OpenWebUI Frontend: `127.0.0.1:3000:8080`
- **Authentication**: `WEBUI_AUTH=True` is strictly set in the production compose profile.
- **Destructive API Safety**: `PTB_ENABLE_DESTRUCTIVE_API=false` is enforced in production, preventing database resets or arbitrary table drops.
- **CORS Restriction**: `PTB_CORS_ORIGINS` defaults to authorized local origins (`http://127.0.0.1:3000,http://localhost:3000`).

### 2.2 Unprivileged Container User (`Dockerfile`)
- Multi-stage build separates build-time dependencies (using `uv`) from the final lean runner container.
- Dedicated unprivileged system user `ptbuser` (`groupadd -r ptbuser && useradd -r -g ptbuser -d /app -s /bin/bash ptbuser`).
- Runtime data directories (`/app/data`, `/app/logs`, `/app/.cache`) are initialized and owned by `ptbuser:ptbuser`.
- Container runs under `USER ptbuser` directive.

### 2.3 Secret Leak Prevention (`.dockerignore`)
- Explicitly excludes credentials, environment secrets, and sensitive local files:
  - `.env`, `.env*.local`, `*.pem`, `*.key`
  - `.git`, `.github`, `.venv`, `data/`, `*.gguf`, `__pycache__`

### 2.4 Multi-Tiered CI Workflow (`.github/workflows/ci.yml`)
- **PR Tier**:
  1. Contract tests (`uv run pytest -m "contract" -v`)
  2. Unit tests (`uv run pytest -m "unit" -q`)
  3. Fixture E2E tests (`uv run pytest -m "fixture_e2e" -v`)
  4. Runtime smoke tests (`uv run pytest -m "runtime_smoke" -v`)
  5. Full non-docker suite (`uv run pytest -m "not external_integration" -q`)
  6. Dataset manifest validation (`uv run python -m benchmarks.cli validate --dataset-dir ...`)
  7. Release readiness gates (`uv run pytest tests/test_release_readiness.py -v`)
  8. Cross-platform matrix across Ubuntu, macOS, and Windows on Python 3.11, 3.12, 3.13.
- **Live Neo4j E2E Tier**:
  - Standalone service container job running live Cypher constraints and vertical slice integration (`tests/test_external_integration.py`).
