## Executive Summary

Task **W3-03** verifies and hardens the live integration between Coding Agent clients (Google Antigravity, Cursor, Claude Desktop, Claude Code) and the **Personal Task Board (PTB) FastMCP Server** across both **stdio** (local subprocess) and **HTTP/SSE** (port 8001) transports.

This deliverable verifies end-to-end operation against running live services:
- **Port 8001**: Live FastMCP Server (HTTP/SSE) operating with 10 read-only query tools, 3 standard resources (`ptb://today-plan`, `ptb://tasks`, `ptb://system-health`), and 2 standard prompts (`morning_briefing`, `task_execution_context`).
- **Port 8000**: Live FastAPI REST API serving `/api/tasks`, `/api/today`, and `/health`.
- **Port 7687**: Authoritative Neo4j domain graph database storing unified tasks and status audit transitions.

All CRUD mutations performed via MCP in trusted write mode reflect **immediately** in the REST API and Neo4j database (Single Source of Truth), while authentic coding agent identities (e.g. `CURSOR_AGENT`, `CLAUDE_CODE`, `ANTIGRAVITY_AGENT`) are faithfully attributed in `StatusTransitionAudit` records without permitting unauthorized administrative impersonation (P1-5).

### 2. Coding Agent Simulation & REST API / Neo4j Parity
- Simulated Cursor Agent (`CURSOR_AGENT`) and Claude Code (`CLAUDE_CODE`) executing a full lifecycle:
  1. `get_today_tasks` / reads `ptb://today-plan`.
  2. `create_task` with title `"E2E Live MCP Mutation Task"`, priority `88.0`, actor `"CURSOR_AGENT"`.
  3. Immediate verification via REST API (`http://127.0.0.1:8000/api/tasks/{task_id}`): status `TODO`, score `88.0`.
  4. Immediate verification via Neo4j Cypher query: node `(:UnifiedTask {id: $id})` exists.
  5. `update_task_status` to `"IN_PROGRESS"`: REST API reflects `"IN_PROGRESS"`, and Neo4j records `(:StatusTransitionAudit {change_actor: "CURSOR_AGENT", new_status: "IN_PROGRESS"})`.
  6. `update_task`: metadata update (priority `98.0`) reflects on REST API.
  7. `delete_task` with `confirm=False`: destructive safeguard aborts action with structured message (`Destructive action aborted: confirmation required`).
  8. `delete_task` with `confirm=True`: soft-deletes task, transitioning status to `"DISMISSED"` across REST API and Neo4j.

### 3. Security, Permissions & Impersonation Boundaries (P1-5, P0-2, W1-02)
- **Actor Impersonation Guard (P1-5)**:
  - Reserved administrative actors (`ADMIN`, `SYSTEM`, `ROOT`, `SUPERUSER`) are rejected with `PermissionError` / `{"success": False, "error": "Impersonation forbidden..."}` unless the client supplies a valid `admin_key` matching `PTB_ADMIN_KEY`.
  - Normal coding agent actors (`CURSOR_AGENT`, `CLAUDE_CODE`, `CODING_AGENT`) are permitted and attributed in audit logs.
- **Read-Only Mode Protection**:
  - Calling mutation tools on a read-only server returns `CallToolResult(is_error=True, text="Unknown tool: create_task")`. State mutations are strictly impossible.
- **HTTP/SSE Transport Security Middleware**:
  - When `PTB_API_KEY` is configured:
    - Missing or invalid key yields `HTTP 401 Unauthorized` with `WWW-Authenticate: ApiKey`.
    - Valid key accepted via `X-PTB-API-KEY` header, `Authorization: Bearer <token>`, or `?api_key=<token>` query parameter.
    - `/health` endpoint is exempt from authentication (HTTP 200).
  - When `PTB_API_KEY` is unset: operates in development mode with warning logs.
- **Zero Secrets Leakage (P1-8)**:
  - Verified no API key fragments or tokens appear in health endpoints, resources, responses, or source code.

## Security & Compatibility Impact

- **Zero Breaking Changes:** Backward compatibility maintained for all 10 read-only query tools.
- **Actor Identity Protection:** Solves P1-5 vulnerability where external agents could inject `actor="ADMIN"`.
- **Destructive Action Protection:** Destructive deletions without explicit `confirm=True` are rejected before hitting the database.
- **Transport Security:** Conforms to P0-2 / W1-02 security directives. Remote callers cannot execute write operations without authentication.
- **Single Source of Truth:** Mutations performed via MCP immediately update Neo4j, making changes immediately visible in OpenWebUI and REST API.
