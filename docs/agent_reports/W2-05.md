## 2. Technical Architecture & Design

### 2.1 Slack Adapter (`slack_adapter.py`)

#### Thread Resolution & Parent Linkage
Slack threads contain a parent message and 0 or more replies:
```
[Channel C_DEV]
  │
  ├── [Parent Message] ts="1727700000.000100" (external_id=ts, parent_external_id=None)
  │     │
  │     ├── [Thread Reply 1] ts="1727700060.000200" (external_id=ts, parent_external_id="1727700000.000100")
  │     └── [Thread Reply 2] ts="1727700120.000300" (external_id=ts, parent_external_id="1727700000.000100")
```
When `conversations.history` detects `reply_count > 0` or `thread_ts == msg["ts"]`, it invokes `_fetch_thread_replies()` using `conversations.replies?channel={channel}&ts={thread_ts}`. The first item returned by Slack is the parent itself and is safely skipped to avoid duplicate emissions.

#### User Profile Resolution
Slack events contain raw user IDs (e.g. `U12345`). The adapter maintains an in-memory `_user_cache`:
1. Check `_user_cache[user_id]`. If found, return immediately without network call.
2. If absent and token is available, execute `users.info?user={user_id}` with exponential retry.
3. Parse `profile.display_name` -> `profile.real_name` -> `name` -> `user_id`.
4. Cache result. In case of network/user failure, fall back gracefully to `user_id`.

#### Rate Limiting & Cursor Pagination
- Inspects response `ok` flag: if `False` and `error == "ratelimited"`, parses `response_metadata.retry_after` and invokes `handle_rate_limit()`.
- Reads `response_metadata.next_cursor` from `conversations.history`, `conversations.replies`, and `conversations.list`. Loops until `next_cursor` is empty or `has_more` is `False`.

### 2.2 GitHub Adapter (`github_adapter.py`)

#### Issues, Pull Requests & Comments
GitHub REST API v3 returns both Issues and Pull Requests under `/repos/{owner}/{repo}/issues`.
- PRs contain the `"pull_request"` key in their JSON payload. The adapter labels them as `[GitHub Pull Request #{number}]` vs `[GitHub Issue #{number}]`.
- Issues with `comments > 0` trigger `_fetch_issue_comments()`, mapping each comment to `RawEventRecord` with `external_id = f"comment-{comment_id}"` and `parent_external_id = str(issue_number)`.

#### Updates / Edits Tracking
GitHub's `/issues` endpoint accepts `since={ISO_TIMESTAMP}`:
```
GET /repos/{owner}/{repo}/issues?state=all&sort=updated&direction=asc&since=2026-10-01T10:00:00Z
```
- When an issue is updated (e.g., status changed to closed, labels added, or body edited), GitHub returns the issue with an updated `updated_at`.
- The adapter computes a new `content_hash` reflecting the modified state. Because the canonical `idempotency_key` incorporates `content_hash`, this emits a new record representing the revision.

#### GraphQL Querying
The `execute_graphql(query, variables)` method sends `POST /graphql` with Bearer auth, checks for errors in `data.get("errors")`, and raises `AcquisitionError` if GraphQL execution fails.

#### Secondary Rate Limit Handling
GitHub enforces both primary hourly rate limits (5,000 req/hr) and secondary abuse limits.
- On HTTP 429 or HTTP 403 where `X-RateLimit-Remaining == "0"`:
  - Adapter reads `X-RateLimit-Reset` (UNIX epoch seconds).
  - Computes `reset_delay = reset_epoch - current_epoch`.
  - Passes wait duration into `handle_rate_limit(reset_delay)`.

### 2.3 Confluence Adapter (`confluence_adapter.py`)

#### XHTML Storage Format Parsing & Action Items
Confluence stores page bodies in Atlassian XHTML Storage Format.
`parse_confluence_storage()` extracts:
1. `<ac:task>` elements:
   - `<ac:task-status>complete|incomplete</ac:task-status>` -> converts to `[x]` or `[ ]`.
   - `<ac:task-body>` -> extracts plain text and resolves user mentions `<ri:user>`.
2. Mentions: Converts `<ri:user ri:account-id="...">` to `@account_id` or `@username`.
3. Action items are rendered into a dedicated section in `normalized_text`:
   ```markdown
   [Confluence: Platform Engineering Architecture] (Space: ENG, v3)

   Architecture roadmap for Q4 services...

   Action Items:
   - [ ] Deploy Neo4j cluster to production @acc-123
   - [x] Benchmark deduplication pipeline latency
   ```

#### Version History Tracking
Each page event tracks `version.number` and `version.when`. When a page is updated from v1 to v2, `normalized_text` and `raw_payload` reflect the new version number and timestamp, producing a distinct deterministic content hash for revision auditing.

#### Confluence Query Language (CQL) Support
The adapter supports flexible CQL search:
- Standard space stream: `space = "{stream_id}" AND type in (page, blogpost) AND lastModified >= "{since}" ORDER BY lastModified ASC`
- Custom CQL stream prefix (`cql:...`): Allows callers to pass custom expressions such as `cql:type = page and label in ('meeting-notes', 'action-items')`.

### 2.4 Multi-Tenant Isolation & Secret Redaction

#### Multi-Tenant Invariant
Every emitted `RawEventRecord` is validated against `adapter.tenant_id`:
```python
idempotency_key = compute_idempotency_key(
    tenant_id=self.tenant_id,
    source_type=self.source_type,
    stream_id=stream_id,
    external_id=external_id,
    content_hash=content_hash,
)
```
Tests in `test_slack_github_confluence_adapters.py` verify that Tenant A and Tenant B consuming identical external messages produce mutually exclusive `idempotency_key`s and separate checkpoints.

#### PII & Secret Redaction
All three adapters sanitize sensitive credentials before recording them into `normalized_text` or error logs:
- Slack bot/user tokens: `xox[baprs]-[0-9a-zA-Z-]{10,}` -> `[REDACTED_SLACK_TOKEN]`
- GitHub tokens: `gh[pousr]_[A-Za-z0-9_]{36,}` and `github_pat_[A-Za-z0-9_]{50,}` -> `[REDACTED_GITHUB_TOKEN]`
- Atlassian tokens: `ATATT[A-Za-z0-9_\-=]{40,}` -> `[REDACTED_ATLASSIAN_TOKEN]`
- Bearer tokens: `Bearer\s+[A-Za-z0-9_\-\.~+/]+=*` -> `Bearer [REDACTED_TOKEN]`
- Basic auth headers: `Basic\s+[A-Za-z0-9+/=]{10,}` -> `Basic [REDACTED_BASIC_AUTH]`
- Embedded URL credentials: `https://user:password@host` -> `https://[REDACTED_USER]:[REDACTED_PASS]@host`

## 4. Security, Isolation & Compatibility Impact

1. **Zero Secret Leakage:**
   - Bot tokens, PATs, Basic auth strings, and passwords in deep links or text bodies are stripped and replaced with deterministic redaction tags.
2. **Tenant Isolation:**
   - Guaranteed by `self.build_raw_event()`. Checkpoints and RawEvent records are strictly partitioned by `tenant_id`. Two tenants syncing identical Slack channels or GitHub repos produce distinct Neo4j nodes and separate journal entries.
3. **Idempotency & Replay:**
   - Replaying identical external datasets against `AcquisitionPipeline` yields 0 duplicates.
4. **Resilience:**
   - Rate limit responses (HTTP 429) do not crash the pipeline; they trigger exponential pauses and resumption.
   - Authentication errors (HTTP 401/403) fast-fail and update the adapter health status to `auth_required` without infinite retry loops.
