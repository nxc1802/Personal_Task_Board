# Personal Intelligence Platform v1

**Personal Intelligence Platform single-user, cross-platform, Neo4j-only, Graphiti-first, OpenWebUI-first**, với acquisition đầy đủ và ưu tiên tự động hóa mạnh.

Có một thay đổi quan trọng về cách mô tả hệ thống: do LLM mặc định chạy qua OpenAI-compatible cloud API, hệ thống vẫn là **local-first về storage/runtime**, nhưng **không phải local-only về dữ liệu**. Nội dung được gửi đến LLM/embedding provider có thể rời máy tùy endpoint cấu hình.

## 1. Architecture Freeze

# 2. Canonical domain model cần thay ngay

Schema cũ `Task / SourceItem / Outbox` nên bị loại bỏ. Schema canonical v1 nên là:

| Node | Vai trò |
|---|---|
| `UnifiedTask` | Task duy nhất của hệ thống |
| `Evidence` | Bằng chứng nguồn |
| `Commitment` | Cam kết/lời hứa cụ thể |
| `Person` | Canonical identity |
| `SourceIdentity` | Teams/Jira/email/account identity |
| `Project` | Project/workspace |
| `Customer` | Customer/organization |
| `Tenant` | Source tenant |
| `RawEvent` | Payload acquisition nguyên bản |
| `IngestionCheckpoint` | Cursor/offset/checkpoint từng source |
| `ProcessingAttempt` | Retry/audit processing |
| `Decision` | Architecture/technical decision |
| `Lesson` | Lesson learned |
| `Incident` | Incident/problem |
| `Document` | Knowledge/document reference |

Các relationship core:

```text
(Person)-[:HAS_IDENTITY]->(SourceIdentity)

(Person)-[:ASSIGNED_TO]->(UnifiedTask)
(Person)-[:REQUESTED]->(UnifiedTask)
(Person)-[:COMMITTED_TO]->(UnifiedTask)

(UnifiedTask)-[:HAS_EVIDENCE]->(Evidence)
(Commitment)-[:HAS_EVIDENCE]->(Evidence)
(Commitment)-[:MATERIALIZES_AS]->(UnifiedTask)

(UnifiedTask)-[:BELONGS_TO]->(Project)
(UnifiedTask)-[:BLOCKED_BY]->(UnifiedTask)
(UnifiedTask)-[:RELATED_TO]->(UnifiedTask)

(Evidence)-[:DERIVED_FROM]->(RawEvent)

(Decision)-[:AFFECTS]->(Project|UnifiedTask)
(Lesson)-[:DERIVED_FROM]->(Incident|UnifiedTask|RawEvent)

(RawEvent)-[:FROM_IDENTITY]->(SourceIdentity)
(RawEvent)-[:PROCESSING_ATTEMPT]->(ProcessingAttempt)
```

`SourceItem` không còn cần thiết vì `RawEvent + Evidence` đã đảm nhiệm hai vai trò provenance và normalized evidence.

# 3. Task state machine

Theo các decision 11 + 21, mình sẽ tách **authoritative state** và **inference state**.

```text
Authoritative status
────────────────────
TODO
IN_PROGRESS
BLOCKED
DONE
DISMISSED
```

System được phép tự động:

```text
TODO → IN_PROGRESS
TODO → BLOCKED
IN_PROGRESS → BLOCKED
BLOCKED → IN_PROGRESS
```

khi có evidence đủ mạnh.

`DONE` nên vẫn cần một tín hiệu authoritative hơn: user action, Jira/Shortcut closed state, merged PR được map rõ ràng, hoặc completion event deterministic. LLM đơn thuần chỉ sinh:

```text
inferred_status = LIKELY_DONE
```

Điều này giữ automation cao nhưng tránh trường hợp một câu “xong phần API rồi” vô tình đóng cả task lớn.

Mỗi auto transition phải tạo audit record:

```text
old_status
new_status
reason
source_evidence_ids
confidence
changed_at
change_actor = SYSTEM
```

# 4. Confidence và auto-merge

Quyết định “đặt confidence thấp để ưu tiên merge” nên được thực hiện bằng cách **tách hai loại confidence**, không dùng một số duy nhất.

`extraction_confidence` trả lời “đây có phải task/cam kết không?”. `correlation_confidence` trả lời “candidate này có phải cùng task với task đã tồn tại không?”.

Baseline mình sẽ freeze:

| Decision | Threshold |
|---|---:|
| Task extraction auto-accept | `>= 0.65` |
| Extraction review | `0.40–0.64` |
| Ignore semantic candidate | `< 0.40` |
| Auto-merge có deterministic anchor | `>= 0.55` |
| Auto-merge không có deterministic anchor | `>= 0.70` |
| Identity auto-link | exact stable ID/email only |

Deterministic anchor gồm Jira key, Shortcut story ID, PR/commit reference, source deep-link, explicit task ID, hoặc một external relationship rõ ràng.

Nếu chỉ giống title về semantic thì không nên hạ threshold quá thấp. Sai merge nguy hiểm hơn duplicate vì nó làm provenance của hai công việc bị trộn vào nhau.

Để vẫn ưu tiên automation, hệ thống sẽ có **split task** sau này: merge mạnh tay hơn, nhưng mọi Evidence vẫn giữ provenance nên có thể tách lại.

# 5. Raw data retention trong Neo4j

Bạn chọn giữ toàn bộ và không backup. Vì Neo4j-only, raw ingestion sẽ lưu kiểu:

```text
(:RawEvent {
    id,
    source_type,
    external_id,
    tenant_id,
    event_timestamp,
    captured_at,
    payload_json,
    normalized_text,
    content_hash,
    idempotency_key,
    processing_status
})
```

`payload_json` nên là JSON serialized string thay vì cố map toàn bộ object vào properties.

Điểm cần phân biệt: “toàn bộ” hợp lý với message/email body, metadata, tool logs và JSON payload. **Binary attachment lớn** không nên nhét trực tiếp vào Neo4j; Neo4j không phải object storage. Với attachment, v1 nên giữ metadata, hashes, filename, source URL/deep-link và extracted text nếu có.

Không có retention cleanup theo quyết định hiện tại.

# 6. Identity resolution

Câu 14 của bạn thực tế mô tả Microsoft authentication, và phần đó đã có code cookie/session.

Identity resolution mình freeze theo default:

```text
AAD object ID / account ID / exact email
            ↓
        auto map
```

Tên giống nhau, fuzzy name hoặc cross-tenant alias sẽ chỉ dùng làm **candidate signal**, không tự hợp nhất Person.

Đây là điểm mình không hạ confidence cùng task correlation, vì merge nhầm hai con người sẽ làm hỏng toàn bộ attribution phía sau.

“Full” sẽ được hiểu là target scope cuối cùng gồm:

| Group | Sources |
|---|---|


| **P7 — Intelligence** | priority, stale, waiting, auto status inference, filters | Today Board deterministic |
| **P8 — Application Layer** | shared query/use-case layer | UI/MCP không có business logic riêng |

# 14. Definition of Ready-to-use sau các decision mới

Release v1 được xem là Ready-to-use khi:

```text
docker compose up infrastructure
        +
ptb acquisition/processing start
        ↓
source activity
        ↓
RawEvent persisted in Neo4j
        ↓
restart process
        ↓
resume đúng checkpoint
        ↓
extract / correlate / auto-merge
        ↓
UnifiedTask + Evidence
        ↓
Graphiti context
        ↓
priority + inferred status
        ↓
OpenWebUI Custom Board
        ↓
filter / inspect / edit / dismiss / mark done
        ↓
coding agent reads same context through MCP
```

Cross-platform release gate cần chạy trên **Windows + macOS + Linux** cho core services. Source adapters phụ thuộc filesystem cụ thể của từng coding agent có thể báo `unsupported/not-installed` thay vì fail toàn hệ thống.

Không có backup/restore gate, không có OS auto-start gate, và không có redaction gate theo quyết định của bạn.

## Một thay đổi mình khuyên thực hiện ngay

Commit tiếp theo **không nên là Layer 2 implementation**. Nó nên là một commit/PR dạng:

**`refactor(core): freeze Neo4j-only v1 architecture and remove dual-store legacy`**

PR đó nên hoàn thành P0 + phần schema của P1: xóa Supabase/outbox, chuyển `Task → UnifiedTask`, thêm `Evidence/Commitment/RawEvent/Checkpoint`, thống nhất status enum, sửa contracts/tests/docs và thiết lập nền cho processing.

Sau PR này, code mới bắt đầu có một “source of truth” đủ ổn định để xây phần còn lại mà không phải rewrite giữa chừng.

OpenWebUI hiện cũng cho phép kết nối trực tiếp OpenAI-compatible provider, phù hợp với quyết định dùng cloud model qua API chuẩn OpenAI. :chatgpt-content-reference{index="3"} Neo4j Community hiện hỗ trợ vector index, nên semantic retrieval không bắt buộc phải thêm vector database thứ hai. :chatgpt-content-reference{index="4"}
