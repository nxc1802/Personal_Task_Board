# Plan 1 — Fix Mixed-State Source Health

## Mục tiêu

Sửa `ApplicationService.get_sources_health()` để health API luôn phản ánh **toàn bộ source đã biết/cấu hình**, thay vì chỉ những source đã có checkpoint.

Hiện có edge case:

```text
Git       HEALTHY
Teams     AUTH_REQUIRED
Outlook   NEVER_SYNCED
Jira      DISABLED
Shortcut  UNCONFIGURED
```

nhưng response có thể chỉ chứa:

```text
Git HEALTHY
```

vì code hiện chia thành:

```python
if checkpoints:
    # chỉ render source có checkpoint
else:
    # render source chưa sync
```

Sau sửa, hệ thống phải luôn tạo health entry cho tất cả source và hợp nhất:

```text
source config
+ runtime state
+ checkpoint state
→ final truthful health state
```

# Bước 2 — Xây source registry trước

Thay logic:

```text
checkpoint → source
```

bằng:

```text
known/configured source
        ↓
find matching checkpoints
        ↓
apply runtime state
        ↓
derive final status
```

Có thể tổ chức nội bộ thành:

```python
source_registry = {
    "ms_teams": {...},
    "ms_outlook": {...},
    "coding_agent": {...},
    "git": {...},
    "jira": {...},
    "shortcut": {...},
}
```

Sau đó index checkpoints:

```python
checkpoints_by_source = ...
```

Và build một `CoverageTenantStatus` cho từng source.

# Bước 3 — Định nghĩa precedence rõ ràng

Agent phải dùng một precedence deterministic, ví dụ:

```text
DISABLED
    ↓
ERROR
    ↓
AUTH_REQUIRED
    ↓
UNCONFIGURED
    ↓
DEGRADED
    ↓
NOT_INSTALLED
    ↓
NEVER_SYNCED
    ↓
HEALTHY
```

Không nhất thiết đúng chính xác thứ tự trên cho mọi source, nhưng phải có rule rõ và test được.

Các behavior bắt buộc:

```text
enabled=false
→ DISABLED
```

```text
Microsoft enabled + session missing/expired
→ AUTH_REQUIRED
```

```text
Jira/Shortcut enabled + thiếu credentials
→ UNCONFIGURED
```

```text
enabled + chưa từng có checkpoint
→ NEVER_SYNCED
```

```text
checkpoint quá cũ
→ DEGRADED
```

```text
recent successful checkpoint
→ HEALTHY
```

```text
runtime adapter error
→ ERROR hoặc DEGRADED
```

Runtime error phải thắng checkpoint cũ đang healthy.

---

# Bước 4 — Xử lý multi-stream source

Một source có thể có nhiều checkpoint.

Ví dụ:

```text
Git
├─ repo-A HEALTHY
└─ repo-B DEGRADED
```

Final Git health không được là `HEALTHY`.

Nên aggregate theo trạng thái xấu nhất.

Tương tự:

```text
Microsoft source
multiple streams
```

không được để một stream mới sync che một stream stale nếu semantics hiện tại coi cả source là một health unit.

---

# Bước 5 — Không fabricated health

Các invariant bắt buộc:

```text
No checkpoint
≠ HEALTHY
```

```text
No login
≠ HEALTHY
```

```text
Missing credentials
≠ HEALTHY
```

```text
Disabled source
≠ NEVER_SYNCED
```

```text
Legacy checkpoint for disabled source
→ vẫn DISABLED
```

Không set:

```text
last_successful_sync = now
```

nếu chưa có sync thật.

# Bước 6 — Sửa overall health aggregation

Sau khi có toàn bộ source entries, tính:

```text
ERROR
→ critical/not_ready tùy current contract

AUTH_REQUIRED
UNCONFIGURED
DEGRADED
NEVER_SYNCED
→ degraded/not_ready tùy semantics

all enabled relevant sources healthy
→ healthy
```

Quan trọng là `overall_health` phải tính từ **toàn bộ source registry**, không chỉ những source có checkpoint.

Không đổi response schema nếu không cần.
