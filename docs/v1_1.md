# 2. Phase R0 — Fix correctness blockers

Đây là phase bắt buộc phải làm trước mọi feature khác.

| Hạng mục | Thay đổi |
|---|---|
| Checkpoint tenant bug | `AcquisitionPipeline.get_checkpoint()` phải truyền đúng `tenant_id` |
| Checkpoint identity | Dùng deterministic ID hoặc composite uniqueness `(tenant_id, source_type, stream_id)` |
| Duplicate checkpoints | Migration xóa/merge checkpoint duplicate |
| Raw event uniqueness | Unique `idempotency_key` ở DB level |
| Task timestamps | Task mới phải có `created_at`; update mới đổi `updated_at` |
| Evidence timestamp | Lấy timestamp từ source event, không dùng thời gian processing |
| Person contract | Thống nhất `id` / `canonical_id` |
| Task status | Python, TS, Neo4j, REST cùng enum uppercase |
| Legacy outbox | Xóa toàn bộ `GraphOutboxEventPayload`, `GraphActionType` còn sót trong TS |
| Ontology/schema | Đồng bộ `StatusTransitionAudit`, node count, relationships |
| Dev seed | Bỏ khỏi `ptb init`; chuyển thành `ptb dev-seed` |

Exit gate của R0 là restart acquisition nhiều lần không tạo duplicate checkpoint/event và Python ↔ TypeScript ↔ Neo4j không còn vocabulary drift.

# 3. Phase R1 — Hoàn thiện Neo4j single-store

Neo4j sẽ là **source of truth duy nhất**, đúng với quyết định trước đó.

Nên thêm/chuẩn hóa các constraints:

```text
RawEvent.id
RawEvent.idempotency_key

UnifiedTask.id
Evidence.id
Commitment.id

Person.canonical_id
SourceIdentity.id

IngestionCheckpoint.id
(tenant_id, source_type, stream_id) unique

ProcessingAttempt.id
StatusTransitionAudit.id
```

`RawEvent` nên có lifecycle rõ:

```text
PENDING
  ↓
PROCESSING
  ↓
PROCESSED

PROCESSING
  ↓
RETRY
  ↓
PROCESSING

RETRY exhausted
  ↓
FAILED
```

Cần lưu:

```text
processing_attempt_count
last_processing_error
next_retry_at
processed_at
processor_version
```

Điều này thay thế nhu cầu external queue/database nhưng vẫn đáp ứng Neo4j-only.

# 4. Phase R2 — Productionize Layer 1, Playwright-first

Đây là thay đổi lớn nhất đối với acquisition hiện tại.

## Microsoft session lifecycle

Luồng setup chính thức:

```text
ptb login microsoft
       ↓
headed Chromium
       ↓
user login Teams / Outlook
       ↓
verify authenticated pages
       ↓
save Playwright storage_state
       ↓
PTB runtime reuses session
```

Không nên coi:

```python
cookie_count > 0
```

là session valid.

Health check phải thực sự xác nhận một authenticated Teams/Outlook page hoặc response.

Runtime cần có state:

```text
UNCONFIGURED
LOGIN_REQUIRED
STARTING
HEALTHY
DEGRADED
AUTH_EXPIRED
ERROR
```

Nếu nhận `401/403`, redirect về login hoặc mất authenticated state:

```text
AUTH_EXPIRED
```

và UI phải báo cho user chạy lại login.

## Teams/Outlook pipeline

Hiện tại cần bỏ kiến trúc:

```text
Playwright
→ LocalIngestionQueue RAM
```

và chuyển thành:

```text
Playwright Response
→ Interceptor
→ RawEventRecord
→ AcquisitionPipeline
→ RawEventRepository
→ Neo4j
```

Một bounded async queue vẫn có thể tồn tại sau đó để giảm blocking, nhưng event chỉ được coi là captured sau khi Neo4j đã ghi thành công.

## Backfill với Playwright

Do không sử dụng Graph API, backfill phải được thiết kế đúng bản chất của web UI.

PTB nên có một **bootstrap capture sweep**:

```text
open Teams
→ load chat/activity surfaces
→ controlled navigation/scroll
→ capture responses

open Outlook
→ inbox/relevant folders
→ controlled navigation/scroll
→ capture responses
```

Không nên claim “complete Microsoft history” nếu web UI không tải lịch sử đó.

Thay vào đó source health nên hiển thị coverage:

```text
Live interception: HEALTHY
Bootstrap sweep: COMPLETED
Oldest captured event: 2026-08-15
Newest captured event: 2026-09-29
```

Như vậy hệ thống nói đúng dữ liệu thực tế mà Playwright quan sát được.

Đây hiện là missing link lớn nhất.

Các component đã có nhưng chưa được orchestration. Cần tạo:

```text
services/processing/

```

```text
get PENDING RawEvents
        ↓
mark PROCESSING
        ↓
parse / normalize
        ↓
identity resolution
        ↓
heuristic filter
        ↓
LLMStructuredExtractor
        ↓
AttributionValidator
        ↓
confidence gate
        ↓
correlation candidate search
        ↓

        ↓

        ↓

        ↓
```


# 7. Phase R5 — LLM processing hardening

Cloud OpenAI-compatible API vẫn là mặc định theo User Decision.

Cấu hình canonical:

```text
OPENAI_API_KEY
OPENAI_BASE_URL
PTB_EXTRACTION_MODEL
PTB_GRAPHITI_MODEL
PTB_EMBEDDING_MODEL
```

Không hard-code provider cụ thể.

Một thay đổi quan trọng: **không silent fallback từ LLM lỗi sang heuristic extractor trong production**.

Nên phân biệt:

```text
LLM unavailable
→ processing RETRY / DEGRADED
```

với:

```text
LLM disabled explicitly
→ heuristic mode
```

Nếu muốn heuristic fallback, user phải bật:

```text
PTB_ALLOW_HEURISTIC_FALLBACK=true
```

Như vậy outage không âm thầm thay đổi chất lượng hệ thống.

# 9. Phase R7 — Graphiti thật

Theo decision trước đó, Graphiti là requirement của v1. Vì vậy implementation hiện tại chưa đủ.

Package:

```text
packages/graph_memory
```

phải thực sự phụ thuộc Graphiti thay vì chỉ dùng “Graphiti principles”.

Cần thay:

```text
custom EpisodicNode Cypher
substring search
```

bằng:

```text
graphiti-core
episode ingestion
entity/fact extraction
temporal relationships
semantic retrieval
```

Neo4j vẫn là database duy nhất.

Graphiti nên được coi là **derived semantic layer**, còn authoritative data vẫn là:

```text
UnifiedTask
Evidence
Decision
Lesson
RawEvent
```

Flow tốt nhất:

```text
Accepted Evidence / Decision / Lesson
             ↓
       Graphiti Episode
             ↓
        semantic graph
```

Nếu Graphiti ingestion lỗi, task creation **không được rollback**. Nó phải retry riêng.

Cũng cần lệnh:

```text
ptb graph rebuild
```

để có thể rebuild semantic memory từ authoritative Neo4j domain data.

# 22. Thứ tự PR/commit mình khuyên triển khai

Để giảm regression, mình sẽ chia thành một chuỗi thay đổi có dependency rõ ràng:

1. **`fix(storage): repair checkpoints, constraints and canonical contracts`** — sửa checkpoint tenant/composite uniqueness, timestamps, TS drift, seed và constraints.
2. **`refactor(acquisition): unify all sources behind durable Neo4j ingestion`** — đặc biệt nối Teams/Outlook Playwright trực tiếp vào `AcquisitionPipeline`.
3. **`feat(processing): add durable RawEvent ProcessingWorker`** — hoàn thành pipeline thật và retry lifecycle.
4. **`feat(correlation): wire task matching and merge into processing`** — từ component thành runtime.
5. **`feat(graph-memory): replace pseudo-Graphiti layer with graphiti-core`** — episode ingestion/search/rebuild.
6. **`feat(intelligence): wire priority and inference into task lifecycle`**.
7. **`feat(application): expose ApplicationService through FastAPI`** — port 8000.
8. **`fix(mcp): run actual FastMCP server and isolate port 8001`**.
9. **`feat(openwebui): connect board to live PTB backend and remove production mocks`**.
10. **`feat(runtime): implement cross-platform ptb run/login/doctor/status supervisor`**.
11. **`test(e2e): add Neo4j vertical-slice and cross-platform CI`**.
12. **`docs(release): reproducible clean-machine setup and Ready-to-use validation`**.

Không nên merge thêm source adapter hay tính năng AI mới trước khi ít nhất PR 1–4 hoàn tất.

# 23. Release gate cuối cùng

Mình chỉ gắn nhãn **Ready-to-use v1** khi workflow này chạy thật:

```text
fresh machine
    ↓
install PTB
    ↓
docker compose up
    ↓
ptb init
    ↓
ptb login microsoft
    ↓
ptb openwebui install
    ↓
ptb doctor = PASS
    ↓
ptb run
    ↓
Teams/Outlook activity captured through Playwright
    ↓
RawEvent exists in Neo4j
    ↓
ProcessingWorker processes it
    ↓
UnifiedTask / Evidence created or merged
    ↓
Graphiti receives episode
    ↓
priority/status inference updated
    ↓
task appears on OpenWebUI Board
    ↓
user updates task
    ↓
restart PTB
    ↓
checkpoint resumes correctly
    ↓
no duplicate event/task
    ↓
MCP reads identical live context
```

Nếu flow này pass, cộng với CI cross-platform và không còn production mock/false-health, mình sẽ đánh giá dự án ở **~90–95% Ready-to-use**. Phần còn lại chủ yếu là edge cases và polish, không còn architectural blocker.

Điểm ưu tiên tuyệt đối hiện tại là **R0 → R4**: sửa storage correctness, unify Playwright acquisition, tạo ProcessingWorker và wire correlation. Chỉ bốn nhóm này đã biến dự án từ “nhiều component hoàn chỉnh riêng lẻ” thành **một Personal Task Board thực sự vận hành end-to-end**.

Mình cũng có thể tạo một hình kiến trúc/roadmap trực quan cho toàn bộ plan này.
