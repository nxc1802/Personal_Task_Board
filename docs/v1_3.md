Dựa trên trạng thái `ade6a68` và các blocker còn lại, mình đề xuất **4 Wave chính, mỗi Wave chỉ 2–3 Sub-Agent**, tổng cộng khoảng **9 lượt Sub-Agent**. Cách này đủ song song hóa nhưng tránh tình trạng chia quá nhỏ làm tăng chi phí merge, review và context switching.

Mục tiêu là sau Wave 4, V1 đạt trạng thái **Release Candidate thực sự**, chỉ còn external integration với Neo4j/OpenWebUI thật khi có môi trường Docker.

# Wave 1 — Runtime Correctness Foundation

Đây là Wave bắt buộc làm trước vì các Wave sau dựa trên correctness của checkpoint, health và runtime contracts.

### Sub-Agent 1A — Checkpoint & Acquisition Correctness

Phạm vi tập trung chỉ vào Layer 1 persistence/checkpoint.

Cần sửa:

```text
AcquisitionPipeline
    ↓
get_checkpoint(
    source_type,
    stream_id,
    tenant_id=self.tenant_id
)
```

và bảo đảm cả read/write đều dùng chính xác:

```text
tenant_id + source_type + stream_id
```

Các việc chính:

- sửa `CheckpointRepositoryProtocol.get_checkpoint()` có `tenant_id`;
- sửa `AcquisitionPipeline.get_checkpoint()`;
- sửa mọi caller checkpoint còn dùng 2 arguments;
- bỏ fallback “single matching checkpoint” khỏi `InMemoryCheckpointRepository`;
- thêm regression test 2 tenant có cùng source/stream;
- test restart/resume không backfill lại;
- test checkpoint của Microsoft tenant, local-user, Jira/Git không cross-contaminate;
- kiểm tra deterministic ID implementation và documentation thống nhất separator;
- lỗi checkpoint phải log `PTB-CKPT-001`, không silent fallback.

**Acceptance gate:**

```text
tenant-A / git / all != tenant-B / git / all

Restart:
checkpoint tenant-A được resume đúng.

Không còn compatibility fallback che lỗi caller.
```

### Sub-Agent 1B — Source Health & Runtime Health Truthfulness

Agent này xử lý toàn bộ health contract để tránh nhiều người sửa `ApplicationService`.

Cần sửa `get_sources_health()`:

Không còn:

```text
no checkpoint
→ healthy
→ last_sync = now
```

Thay bằng state thực:

```text
DISABLED
UNCONFIGURED
NEVER_SYNCED
STARTING
HEALTHY
DEGRADED
AUTH_REQUIRED
ERROR
NOT_INSTALLED
```

Nguồn Microsoft phải dựa trên Playwright session, vì **Playwright là acquisition chính thức**, không có Graph API fallback.

Ví dụ:

```text
Teams enabled + chưa login
→ AUTH_REQUIRED

Git enabled + chưa sync
→ NEVER_SYNCED

Jira disabled
→ DISABLED

Cursor không cài
→ NOT_INSTALLED
```

Cùng lúc sửa `get_system_health()`:

- đọc `ProcessingPipeline.health_status`;
- đọc `GraphitiAdapter.is_available`;
- dùng Playwright session manager thực từ supervisor thay vì tạo session manager mới với path mặc định;
- phân biệt `healthy`, `degraded`, `not_ready`;
- không fake `healthy` nếu chưa có evidence rằng component hoạt động.

**Acceptance gate:**

Clean install không được báo toàn bộ sources healthy.

Neo4j down:

```text
NOT_READY
```

Graphiti down:

```text
DEGRADED
```

Microsoft chưa login:

```text
core system = READY_WITH_WARNINGS
Teams/Outlook = AUTH_REQUIRED
```

### Sub-Agent 1C — Runtime Contract & Anti-Fallback Audit

```text
packages/

integrations/
```

Đặc biệt kiểm tra:

- `mock_mode`;
- heuristic fallback runtime;
- fake success;
- in-memory fallback;

Không cần xóa test doubles trong `tests/`.

Cũng không nên xóa heuristic algorithms hợp lệ nếu chúng là logic thật. Chỉ cấm việc dùng heuristic để giả làm LLM thành công khi LLM lỗi.

**Deliverable của 1C** là patch nhỏ + guard tests, không refactor rộng.

# Wave 2 — Graphiti Production Wiring

Wave này dùng **2 Sub-Agent**, không cần tách Graph client / worker / supervisor thành 3–4 người vì chúng liên quan chặt.

## Sub-Agent 2A — Persistent Graph Sync Lifecycle

Mục tiêu: đưa Graphiti từ “component tồn tại” thành **runtime path thực**.

Production `TaskDomainRepository` khi upsert Evidence cần đánh:

```text
graph_sync_status = PENDING
graph_sync_attempts = 0
```

hoặc dùng một canonical graph-sync record nếu muốn tách metadata.

Flow mong muốn:

```text
ProcessingPipeline
   ↓
TaskDomainRepository
   ↓
UnifiedTask + Evidence committed
   ↓
Evidence graph_sync_status=PENDING
   ↓
return success
```

Graphiti tuyệt đối không nằm trong transaction critical path của Task.

Không làm:

```text
Task upsert
→ gọi Graphiti
→ chờ Graphiti
```

Phải giữ architecture:

```text
Neo4j authoritative write
        ↓
commit
        ↓
async GraphMemorySyncWorker
```

Agent này cũng phải xử lý:

- Decision;
- Lesson;
- Evidence;
- RETRY;
- FAILED;
- attempt count;
- last error;
- synced timestamp;
- idempotent sync.

## Sub-Agent 2B — Supervisor Wiring + Graph Health

Agent này nối worker vào runtime:

```text
PTBProcessSupervisor
├─ ProcessingWorker
├─ GraphMemorySyncWorker   ← thêm
├─ REST
├─ MCP
├─ Playwright
└─ source adapters
```

Cần có:

```text
ptb-graph-sync-worker
```

trong `self.tasks`.

Shutdown:

```text
stop/cancel graph worker
→ close Graphiti client
→ không double-close shared Neo4j client
```

Health phải phản ánh:

```text
Graphiti adapter available   → healthy
Graphiti unavailable         → degraded
Graph sync backlog           → warning/degraded tùy threshold
Neo4j vẫn hoạt động          → task processing không dừng
```

Quan trọng: test không được dùng behavior đặc biệt của `InMemoryTaskDomainRepository` để chứng minh wiring.

### Wave 2 acceptance

Fixture:

```text
RawEvent
→ Task
→ Evidence PENDING
→ Graph worker sweep
→ SYNCED
```

Graphiti failure:

```text
RawEvent
→ Task vẫn tồn tại
→ Evidence RETRY/FAILED
→ PTB-GRAPH-001
→ system DEGRADED
```

Và production supervisor smoke phải xác nhận graph worker thật sự được start.

# Wave 3 — OpenWebUI Production Hardening

Wave này có thể chạy song song Wave 2.

## Sub-Agent 3A — Self-Contained OpenWebUI Plugins

Hiện Tools/Functions import:

```python
ptb_contracts.logging
```

trong khi OpenWebUI image không có package này.

V1 nên tránh custom image nếu không bắt buộc.

Phương án gọn nhất:

```text
ptb_tools.py
ptb_board_action.py
```

phải **self-contained**.

Có thể định nghĩa local helper cực nhỏ:

```text
PTB-OWUI-001
structured stderr logging
```

Không import toàn monorepo.

Không copy cả `ptb_contracts` vào OpenWebUI volume vì sẽ tạo dependency packaging phức tạp.

Cũng cần thống nhất URL.

Một điểm rất quan trọng khi chạy từ Docker:

```text
OpenWebUI container
localhost:8000
```

là chính container đó, **không phải host PTB service**.

Do đó cần quyết định connection chính thức cross-platform.

Khuyến nghị thêm alias vào Compose:

```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

và OpenWebUI plugin mặc định gọi:

```text
http://host.docker.internal:8000
```

Trên macOS/Windows alias đã quen thuộc; Linux compose có mapping trên.

Board chạy browser-side thì vẫn có thể dùng:

```text
http://127.0.0.1:8000
```

Nên phân biệt:

```text
Browser board → 127.0.0.1:8000
Server-side Tool/Function → host.docker.internal:8000
```

Đây là một điểm rất nên test contract.

```text
        ↓
tenant-correct checkpoint
        ↓
ProcessingWorker
        ↓

        ↓
Correlation / Merge
        ↓

        ↓

        ↓

        ↓

        ↓
GraphMemorySyncWorker
        ↓
Graphiti SYNCED / truthful RETRY
        ↓
ApplicationService
       ↙ ↘
     REST MCP
       ↓

```

Và failure paths:

```text
Neo4j unavailable      → NOT_READY
LLM unavailable        → DEGRADED + retry
Graphiti unavailable   → DEGRADED, task unaffected

Application unavailable→ PTB-OWUI-001

```

Với cấu trúc này, **Wave 1 → Wave 2/3 song song → Wave 4** là đường ngắn nhất để hoàn thiện V1 mà không tốn tài nguyên vào quá nhiều Sub-Agent hoặc các refactor không cần thiết.
