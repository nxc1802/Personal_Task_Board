PHẦN 1: Các nguyên nhân khác khiến cửa sổ/tab đăng nhập không hiện lênCấu hình Playwright đang để chế độ ẩn (headless=True)Nguyên nhân: Theo mặc định, mọi trình duyệt do Playwright khởi tạo đều chạy ở chế độ headless=True (chạy ngầm không giao diện). Ngoài ra, các image Docker hoặc file cấu hình .env khi đóng gói thường tự động ép biến môi trường HEADLESS=true để tránh lỗi thiếu thư viện đồ họa (XServer). Khi đó, tiến trình vẫn in ra log Đang mở Microsoft Teams Web... trên màn hình console nhưng trình duyệt thực chất đang chạy ngầm.   Xung đột Profile hoặc kẹt tiến trình trình duyệt cũ (SingletonLock)Nguyên nhân: Nếu script đăng nhập của bạn sử dụng launch_persistent_context (lưu giữ profile trình duyệt cố định) và ở lần chạy trước trình duyệt chưa được đóng đúng cách, tệp khóa (SingletonLock) sẽ ngăn cửa sổ mới bật lên hoặc làm treo lệnh khởi tạo ngay tại bước [*] Đang mở trình duyệt để đăng nhập....   Cửa sổ bị mở ở Session 0 (Background Service) hoặc bị thu nhỏ dưới nềnNguyên nhân: Ngay cả khi bạn gọi script thông qua một tiến trình trung gian trên Windows (như cửa sổ PTB TEAMS Login trong ảnh), nếu tiến trình gọi nó chạy dưới quyền Background Service/Daemon hoặc cửa sổ Chromium mới mở không được cấp quyền chiếm tiêu điểm (Focus Stealing Prevention của Windows), cửa sổ trình duyệt có thể bị ẩn dưới thanh Taskbar hoặc nằm ở tọa độ ngoài màn hình.   Trình duyệt chặn Popup (Nếu mở qua sự kiện bất đồng bộ ở Frontend)Nguyên nhân: Nếu nút bấm trên trang web (127.0.0.1:3000/workspace/models#board) gọi một API (await fetch(...)) xuống Backend để khởi tạo phiên rồi mới dùng window.open() nhằm bật tab mới trên trình duyệt hiện tại, cơ chế Popup Blocker của Chrome sẽ tự động chặn vì lệnh mở tab không diễn ra tức thời ngay tại thao tác click chuột.   PHẦN 2: Các giải pháp khắc phục khi chạy Web và Server qua DockerTùy vào việc bạn muốn giữ kiến trúc 100% trong Docker hay kết hợp giữa Docker và máy chủ Windows, bạn có thể chọn 1 trong 4 cách khắc phục hiệu quả nhất dưới đây:Cách 1: Cho phép Docker điều khiển trình duyệt trên máy chính qua CDP (Khuyên dùng – Nhẹ và ổn định nhất)Thay vì bắt Docker tự mở cửa sổ trình duyệt bên trong container, bạn cho phép Playwright trong Docker kết nối ra trình duyệt Chrome/Edge của máy chính Windows thông qua giao thức Chrome DevTools Protocol (CDP).Trên máy chính (Windows): Mở trình duyệt Chrome/Edge kèm cờ mở cổng debug (có thể gộp dòng này vào file .bat khởi động hệ thống của bạn):DOSstart chrome.exe --remote-debugging-port=9222 --user-data-dir="D:\Working\PTB\chrome-debug-profile"
Trong code Playwright (chạy trong Docker): Thay thế hàm chromium.launch(...) bằng connect_over_cdp trỏ về máy chính thông qua tên miền nội bộ host.docker.internal:Python# Ví dụ với Python Playwright
browser = await p.chromium.connect_over_cdp("http://host.docker.internal:9222")
context = browser.contexts[0] if browser.contexts else await browser.new_context()
page = await context.new_page()
await page.goto("https://teams.microsoft.com")
Kết quả: Khi bạn bấm nút trên web, một tab mới sẽ bật lên ngay trên trình duyệt của máy Windows. Sau khi bạn đăng nhập xong, code chạy trong Docker vẫn gọi context.storage_state(path="...") để thu thập và lưu file storage_state.json vào bên trong container như bình thường.   Cách 2: Chạy Script bắt Cookie trực tiếp ở máy chính + Chia sẻ Volume với DockerQuan sát cửa sổ terminal PTB TEAMS Login trên màn hình của bạn, đường dẫn lưu file đang trỏ về ổ đĩa máy thật: D:\Working\PTB\Personal_Task_Board-main\data\playwright\storage_state.json. Điều này cho thấy bạn đã có cơ chế chạy script ở máy ngoài và dùng chung thư mục data/playwright với Docker qua Volume Mount.   Nếu cửa sổ PTB TEAMS Login đã bật lên trên Windows mà trình duyệt vẫn không hiện, bạn hãy kiểm tra và sửa lại trực tiếp trong file script Python/Node.js đó:   Bắt buộc truyền headless=False và ép hiển thị cửa sổ lên trên cùng:Pythonbrowser = p.chromium.launch(
    headless=False,
    args=["--start-maximized", "--new-window"]
)
Đảm bảo đã cài trình duyệt cho môi trường máy chính: Chạy lệnh playwright install chromium trên terminal của Windows (vì đôi khi môi trường Python trên máy thật chưa tải Chromium nên bị treo ở bước [*] Đang mở trình duyệt để đăng nhập...).   Đảm bảo Docker nhận được file ngay lập tức: Trong docker-compose.yml, kiểm tra chắc chắn thư mục đã được mount:YAMLvolumes:
  - D:/Working/PTB/Personal_Task_Board-main/data/playwright:/app/data/playwright
Cách 3: Đưa giao diện trình duyệt từ Docker lên thẳng trang Web bằng Xvfb + noVNC (Đóng gói 100% trong Docker)Nếu bạn muốn đóng gói toàn bộ tính năng vào trong Docker (để sau này deploy lên server/VPS Linux vẫn đăng nhập MS Teams được mà không cần màn hình Windows):Cài đặt xvfb (màn hình ảo), x11vnc và novnc / websockify vào trong Dockerfile của container chạy Playwright.Mở thêm một cổng cho noVNC (ví dụ cổng 6080).Khi bấm nút đăng nhập trên giao diện 127.0.0.1:3000, trang web của bạn chỉ cần mở một tab mới hoặc nhúng một <iframe> trỏ tới [http://127.0.0.1:6080/vnc.html?autoconnect=true](http://127.0.0.1:6080/vnc.html?autoconnect=true).   Kết quả: Bạn sẽ nhìn thấy và thao tác trực tiếp với cửa sổ trình duyệt Chromium đang chạy bên trong Docker ngay trên giao diện web của mình (hỗ trợ đầy đủ việc nhập mật khẩu và xác thực 2 lớp MFA của Microsoft).Cách 4: Ánh xạ màn hình từ Docker ra Windows qua WSLg (Dành cho Docker Desktop trên Windows 11)Nếu máy bạn đang chạy Windows 11 và Docker Desktop sử dụng nhân WSL2 (có sẵn WSLg hỗ trợ giao diện đồ họa Linux), bạn có thể cho phép container mở thẳng cửa sổ trình duyệt lên màn hình Windows bằng cách thêm cấu hình sau vào docker-compose.yml:YAMLservices:
  your-backend-service:
    environment:
      - DISPLAY=:0
      - WAYLAND_DISPLAY=wayland-0
      - XDG_RUNTIME_DIR=/mnt/wslg/runtime-dir
    volumes:
      - /tmp/.X11-unix:/tmp/.X11-unix
      - /mnt/wslg:/mnt/wslg
(Lưu ý: Trong code Playwright vẫn phải đặt headless=False).Mẹo xử lý nhanh trong lúc phát triển: Trên modal giao diện nền của bạn (phía dưới cửa sổ đen) đã được thiết kế sẵn nút "Lưu Cookie JSON". Nếu bạn cần vượt qua bước này ngay để test các tính năng khác, bạn có thể đăng nhập teams.microsoft.com trên trình duyệt Chrome bình thường, dùng tiện ích mở rộng như Cookie-Editor để Export toàn bộ cookie ra định dạng JSON rồi dán trực tiếp vào ô nhập liệu trên web và bấm Lưu Cookie JSON.
